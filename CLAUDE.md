# Конвенции разработки SN — SNTelegram

Этот файл — стандарт линейки Somikyy Network, лежащий в корне каждого репозитория.
Первая половина одинакова во всех репозиториях SN, вторая — специфика SNTelegram.

---

## Железные правила

Нарушение любого — ревью-блокер, а не вопрос стиля.

1. **Открытый код обязателен, GPL-3.0-or-later.** Заголовок лицензии в каждом `.java`.
   В RU-сегменте после разбора бэкдора в мае 2026 (класс `MutableUtilities`, замаскированный под
   `org.apache.commons.lang3`, воровал всё вплоть до пароля RCON) закрытый jar от неизвестного
   автора читается как угроза по умолчанию. Открытый код — пропуск, а не бонус.

2. **Ноль runtime-зависимостей, если нет очень веской причины.** Всё, что шейдится, — потенциальный
   конфликт на чужом сервере. `compileOnly` для API сервера — норма; `implementation` требует
   обоснования в PR.

3. **Русская локаль из коробки.** Не «перевод потом», а `ru` по умолчанию. Все потоки вывода
   создаются с явным UTF-8.

4. **Ни одного непроверенного утверждения** в коде и в текстах для пользователя. Каждое правило,
   цифра и цитата — с первоисточником. Не нашёл источник — не добавляй, выноси в раздел
   «Правила-кандидаты» спеки со статусом «не подтверждено».

5. **Главный поток священен.** Дисковая и сетевая работа — асинхронно.

6. **Миграция с конкурента — обязательная фича, а не опция.**

7. **Самотест без сети.** Maven Central и repo.papermc.io бывают недоступны; для машины в РФ это
   рабочая ситуация.

8. **Чистое удаление.** Плагин обязан убирать за собой всё, что создал.

## Конвенции кода

- **Java 17** как целевая версия байткода. Компилятор — 21 (иначе Gradle не резолвит paper-api).
- **Пакет:** `network.somikyy.sntelegram`.
- **Слои:** пакет `core` не импортирует `org.bukkit.*` **никогда**. Проверяется грепом в CI.
- **Комментарии объясняют «почему», а не «что».**
- Сообщения пользователю — полными предложениями, без жаргона и кодов ошибок.
- Форматирование: 4 пробела, ширина ~110.

## Специфика SNTelegram

### Слои

```
core/     — HTTP-клиент Telegram, парсер JSON, модель Update/Message, роутер тем,
            конвертация форматов, конфиг, хранилище. Ноль Bukkit-импортов.
bukkit/   — слушатели событий, команды, применение модерации. Единственный слой,
            знающий про сервер.
```

Инвариант проверяется в CI грепом. Он не косметический: `core` должен собираться и
тестироваться без сервера, иначе самотест без сети невозможен.

### Ключевые инварианты

- **Токен бота — секрет.** Никогда не попадает в лог, в сообщение об ошибке, в отчёт об ошибке
  и в вывод команды. При логировании URL токен вырезается.
- **Сетевой поток никогда не трогает мир.** Long polling живёт в своём потоке; всё, что требует
  главного потока (кик, бан, выполнение команды), уходит на планировщик.
- **Мост не роняет чат.** Любая ошибка Telegram гасится и логируется, но никогда не отменяет
  и не задерживает сообщение в игре.
- **Ни одного сообщения в Telegram из-под лока.** Отправка — через очередь с ограничителем
  скорости в отдельном потоке.

### Чего делать не надо

- Не добавлять поле Telegram API «по памяти» — только по документации, с проверкой имени.
- Не шейдить `telegrambots` или любой другой HTTP-клиент: `java.net.http.HttpClient` есть с Java 11.
- Не блокировать главный поток на сетевом вызове.
- Не писать английский интерфейс с русским переводом «потом».
- Не оставлять `TODO` без имени и даты.
- Не помечать `folia-supported: true`, не проверив.
- Не обещать в README того, чего нет в коде.
